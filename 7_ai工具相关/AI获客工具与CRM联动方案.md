# AI获客工具与CRM联动方案（TradePilot + AI获客工具）

> **版本**：1.0
> 
> **更新日期**：2026-09-05
> 
> **适用对象**：有开发能力的外贸团队、技术负责人、销售运营负责人
> 
> **核心目标**：实现“AI自动获客 → 自动录入CRM → 客户回复自动记录 → 人工仅在关键节点介入”的自动化外贸获客闭环


## 📌 一句话核心观点

**AI获客工具负责“找”，TradePilot负责“管”，你在关键节点负责“判”——自动记录，人工决策。**


## ✅ 可行性结论

**完全可以。** 开源工具最大的优势就是可以自由打通各个工具，形成自动化的业务闭环。

- TradePilot 本身就是为1-5人外贸团队设计的，把分散的客户资料、报价、订单、出货放进同一个可自托管工作区。它包含业务 API、输入校验和第三方服务接入说明，因此你完全有能力打通与 AI 获客工具的数据链路。
- 注：可以通过工作流或开发转换脚本实现全自动化

## 🔧 具体实现方案

### 一、线索自动录入（从获客工具到TradePilot）

大多数 AI 获客工具（如 `AI_Find_Customer`、`b2b-buyer-discovery`）都能输出结构化的线索数据（CSV/JSON）。可以通过以下三种方式自动导入 TradePilot：

| 方式 | 实现路径 | 难度 | 说明 |
| :--- | :--- | :--- | :--- |
| **直接 API 调用** | 获客工具输出 JSON → 调用 TradePilot 业务 API 创建客户 | 中 | 需要少量开发，一次投入永久受益 |
| **CSV 批量导入** | 获客工具导出 CSV → TradePilot 手动导入 | 低 | 适合初期试水，不需要写代码 |
| **Webhook 触发** | 获客工具发现新线索 → 自动推送至 TradePilot | 中高 | 最自动化的方式，实现“发现即录入” |

**API 集成要点**：
- TradePilot 包含完整的业务 API，支持客户、询盘、报价、订单等核心对象的创建与更新
- 通过 API Key 认证（API Key 保存在当前浏览器，通过 TradePilot 服务端发起请求）
- 可将获客工具的输出对接到 TradePilot 的客户/询盘模块


### 二、客户回复自动记录

| 场景 | 实现方式 | 说明 |
| :--- | :--- | :--- |
| **邮件回复** | 通过 IMAP/SMTP 集成或邮件转发 | TradePilot 的询盘模块支持状态流转和 AI 回复草稿，邮件回复可通过配置自动关联到对应询盘 |
| **WhatsApp 回复** | TradePilot 的 Chrome 插件 | 插件可主动读取客户对话、分析需求与采购阶段，回复内容可记录在客户档案中 |
| **通用方案** | 人工一键记录 | 收到回复后，在 TradePilot 中快速添加沟通记录，操作路径清晰 |

> **建议**：初期可以采用“AI 获客工具生成线索 → 手动或半自动导入 TradePilot”的混合模式，待流程跑通后再逐步实现全自动化。


### 三、什么时候才需要人工处理？

这正是 TradePilot 的设计哲学——**AI 辅助，人做最终决策**：

| 环节 | 谁来做 | 说明 |
| :--- | :--- | :--- |
| **线索自动录入** | 🤖 自动 | 获客工具发现的线索自动进入 TradePilot 客户池 |
| **询盘状态流转** | 🤖 自动 | AI 可识别客户回复类型，自动更新询盘状态 |
| **AI 回复草稿生成** | 🤖 AI 生成 | AI 根据上下文生成回复草稿 |
| **回复内容发送** | 👤 你确认 | 草稿需要你审核、微调后手动发送——这是“人工介入”的核心节点 |
| **报价确认** | 👤 你确认 | 报价草稿生成后，需要人工接受确认才能转订单 |
| **复杂沟通** | 👤 你处理 | 涉及价格谈判、客诉处理等需要判断力的场景 |
